# External specialist skills

Use this reference only after `software-development` has selected the active Coferlandia role and
when the task matches one of the specialist domains below.

## Authority invariant

External providers are independently installed and upstream-owned. Their skills refine reasoning
inside the already-authorized work contract. They do not expand scope, authorize Git operations,
change approval requirements, own Qualification/Integration/Release, or override repository-local
contracts.

If a recommended specialist is missing, surface the provider, exact skill, concrete benefit, and
canonical repository once for the current task/session, then continue when the Coferlandia contract
has a safe fallback. Installation is never implicit and requires explicit current user approval.

## Addy Osmani Agent Skills map

For `addyosmani/agent-skills`, request these specialists when materially applicable:

- `api-and-interface-design` — public APIs, shared module boundaries, compatibility, idempotency,
  or interface contracts.
- `source-driven-development` — framework/library work whose correctness depends on current,
  version-specific official documentation.
- `security-and-hardening` — authentication, authorization, untrusted input, secrets, personal
  data, dependency/supply-chain risk, or external service boundaries.
- `frontend-ui-engineering` and `browser-testing-with-devtools` — user-facing UI/runtime browser
  work when browser capability is available.
- `performance-optimization` — measured performance work or explicit performance requirements.
- `observability-and-instrumentation` — production telemetry, diagnostics, metrics, traces, alerts.
- `deprecation-and-migration` — approved compatibility transitions or removals.
- `code-simplification` — approved behavior-preserving simplification/refactor scope only.
- `context-engineering` — materially degraded task/session context.

## Never-request lifecycle conflicts

Never auto-request Addy's:

- `using-agent-skills`
- `spec-driven-development`
- `planning-and-task-breakdown`
- `incremental-implementation`
- `test-driven-development`
- `debugging-and-error-recovery`
- `code-review-and-quality`
- `git-workflow-and-versioning`

Coferlandia and its canonical Superpowers dependencies own those lifecycle responsibilities.
In particular, `superpowers:test-driven-development` and
`superpowers:systematic-debugging` remain canonical where `software-development` requires them.
